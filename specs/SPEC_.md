# CRM для Review Business Opportunities

## Summary

Создание CRM-системы для управления бизнес-opportunities, аналогичной Affinity CRM. Система предназначена для команды 10-50 человек и включает управление контактами, компаниями, pipeline сделок с 5 фиксированными стадиями, дашборды с аналитикой и систему напоминаний.

## Технологический стек

- **Frontend**: React
- **Backend**: Node.js (Express)
- **База данных**: PostgreSQL
- **Контейнеризация**: Docker + Docker Compose (для локальной разработки и тестирования)

## Собранные требования

### 1. Функциональность MVP (приоритеты)

**Приоритет 1 - Ядро системы:**
- Управление контактами и компаниями
- Связи между контактами и компаниями (простая модель: 1 контакт → 1 компания)
- Pipeline сделок/opportunities

**Приоритет 2 - Отложено:**
- Интеграция с email
- Автоматический захват данных из email/календаря
- Relationship intelligence

### 2. Pipeline стадии (фиксированные)

1. **Скрининг** - первичная оценка opportunity
2. **Дипдайв** - глубокое изучение
3. **Дью Дилидженс** - проверка и верификация
4. **Сайнинг** - подписание документов
5. **Closed** - сделка закрыта (Won/Lost)

### 3. Поля Opportunity

**Базовые поля:**
- Название opportunity
- Компания (связь)
- Контактные лица (связь)
- Стадия в pipeline
- Сумма сделки
- Ожидаемая дата закрытия

**Дополнительные поля:**
- Источник лида (откуда пришла сделка)
- Кастомные поля (пользователь может добавлять свои)
- Комментарии (история взаимодействий)
- Напоминание/будильник (дата когда вернуться)
- Категории/теги

### 4. Система напоминаний

- Пользователь устанавливает дату напоминания для opportunity
- В назначенную дату отправляется email-уведомление
- Требуется интеграция с email-сервисом (SMTP или сервис типа SendGrid)

### 5. Модель данных - Контакты и Компании

**Компания:**
- Название
- Описание
- Отрасль
- Веб-сайт
- Связанные контакты
- Связанные opportunities

**Контакт:**
- Имя
- Email
- Телефон
- Должность
- Компания (одна, простая связь)

### 6. Роли и права доступа

**Admin:**
- Управление пользователями (создание/удаление аккаунтов)
- Удаление любых данных в системе
- Все права User

**User:**
- Создание/редактирование контактов, компаний, opportunities
- Удаление только своих данных
- Просмотр всех данных

### 7. Интерфейс

**Основной вид - Таблица opportunities:**
- Список всех opportunities в табличном виде
- Сортировка по колонкам
- Фильтрация по стадиям, категориям, дате и т.д.
- Поиск

**Дашборды (отдельная вкладка):**
- Воронка: количество сделок по стадиям
- Суммы: общая сумма сделок по стадиям
- Конверсия между стадиями
- Динамика: сделки закрытые за месяц/квартал
- Топ менеджеров по количеству/сумме сделок
- Фильтры для всех метрик

### 8. Импорт данных

- Импорт контактов из Excel/CSV
- Импорт компаний из Excel/CSV
- Импорт opportunities из Excel/CSV
- Маппинг колонок при импорте

## Edge Cases и Риски

### Edge Cases:

1. **Удаление компании** - что делать с привязанными контактами и opportunities?
   - Решение: Запретить удаление если есть связанные данные, либо каскадное удаление с подтверждением

2. **Удаление пользователя** - что делать с его данными?
   - Решение: Данные остаются в системе, но creator_id становится NULL или переназначается

3. **Большой импорт** - файл с 10000+ строками
   - Решение: Фоновая обработка, прогресс-бар, уведомление по завершении

4. **Дубликаты при импорте**
   - Решение: Проверка по email для контактов, по названию для компаний, предложение обновить или пропустить

5. **Кастомные поля разных типов**
   - Поддержать: текст, число, дата, выпадающий список

### Риски:

1. **Email delivery** - письма могут не доходить
   - Митигация: Использовать проверенный сервис (SendGrid), логировать отправку

2. **Производительность дашбордов** при большом объёме данных
   - Митигация: Кэширование, материализованные представления в PostgreSQL

3. **Безопасность** - SQL injection, XSS
   - Митигация: Prepared statements, sanitization, CORS настройки
